# 포세이큰: 안야의 긴 밤 — AnyasLongNight

Warcraft III Lua 기반의 1인용 생존 액션 커스텀 맵입니다. 플레이어는 안야 또는 퓨트리스를 선택해 직접 이동하고, 자동으로 발동하는 무기와 성장 선택으로 다섯 구역을 돌파합니다.

스트라솔름 폐허에서 이름 모를 언데드의 흔적을 따라 로데론 수도 하수구까지 수색하고, 그를 지하로 이송하는 하룻밤을 그립니다. 가렉이 깨어나는 포세이큰 왕국 본편으로 이어지는 **창작 외전**이며, 수색 여정·대사·이송 경위를 공식 캠페인의 확정 사건으로 다루지 않습니다.

이 문서는 작업 중인 0.1e 변경(무리 돌진·피격 비네트)까지 반영한 구성과 개발 절차를 정리합니다. 맵에 표시되는 버전은 `build/lib/project.mjs`의 `mapVersion`에서 관리합니다. 플레이어 대상 변경 내역은 [PATCH_NOTES.md](PATCH_NOTES.md)에 기록하고, 과거 구현·검증 이력은 Git 이력에서 확인합니다.

## 빠른 시작

Node.js **22 이상**과 기존 테스트 맵이 필요합니다. 아래 명령은 현재 체크아웃의 프로젝트 루트에서 실행합니다.

```powershell
npm ci
npm run build
npm run sync:base
npm test
npm run check
npm run check:base
```

- `build`: 정식 테스트 맵과 통합 Lua를 갱신합니다.
- `sync:base`: 편집용 원본의 실행 Lua·에디터 WCT와 도구가 관리하는 게임 오브젝트·설명을 동기화합니다.
- `test`: 실제 Lua 소스를 Fengari의 Lua 5.3 환경과 Warcraft 네이티브 모의 함수로 검사합니다. 맵을 쓰지 않습니다.
- `check` / `check:base`: 테스트 맵 / 원본이 소스 및 각 도구의 동기화 기준과 일치하는지 읽어서 확인합니다. 불일치 시 종료 코드 1을 반환합니다.

게임 변경은 **원본과 정식 테스트 맵 양쪽에 반영하고 다시 읽어 검증**합니다. `build`만 실행하면 편집용 원본은 갱신되지 않습니다.

기본 플레이 파일은 `dist/AnyasLongNight-playtest.w3x`입니다. 출력 파일이 잠겨 별도 이름으로 저장되면 빌드 완료 메시지의 **실제 출력 경로**를 사용합니다. 실행 전 World Editor에 열려 있던 이전 사본도 다시 열어야 합니다.

시작 무기는 영웅마다 네 가지 중 선택합니다. 소환 무기는 레벨업 후보에 포함됩니다. 기본 체력은 300이고, 플레이어 종족은 언데드입니다.

### 스테이지와 진행

| 구역 | 보스 등장 | 스테이지 제한 시간 |
| --- | --- | --- |
| 1 | 2분 | 3분 |
| 2 | 3분 | 4분 |
| 3~5 | 4분 | 5분 |

보스 처치 즉시 해당 구역을 클리어합니다. 모든 구역의 보스 처치 제한은 등장 후 1분입니다.

대사는 ‘다음 대사’로 직접 넘기며 ‘장면 건너뛰기’를 지원합니다. 마지막 버튼은 상황에 따라 ‘수색 준비’·‘보상 선택’·‘결과 보기’로 표시합니다. 출발·다음 구역 소개가 끝나면 준비 화면에서 **‘수색 시작’ → 3초 카운트다운**을 거쳐 전투를 시작합니다.

성장 선택·확장 인벤토리·특성 등 정보 창·스토리·수색 준비·카운트다운 동안 전투와 관련 시간은 정지합니다. 대사 완료·건너뛰기·가방 닫기만으로 출발하지 않습니다. 위험 수색은 표식에 서 있는 것만으로 수락되지 않으며 직접 수락해야 합니다. 가방이 가득 찼을 때 선택한 장비 보상은 보관하고 빈칸 확보 후 수령합니다.

### 무리 돌진과 피격 표시

전투 중 일정 주기로 근접 대열이 화면 밖에서 영웅 위치를 가로질러 직선 돌진합니다. 돌진 전에는 대열 폭의 붉은 통로·테두리·방향 화살표·경고음으로 예고합니다. 보스 등장 직전에는 시작하지 않고, 공간이 부족하거나 적이 너무 많으면 잠시 후 재시도합니다.

돌진 적은 경로를 바꾸지 않고, 경로가 겹친 영웅에게 한 번씩 피해를 줍니다. 통로 끝에 도착하거나 수명이 끝나면 처치 보상 없이 사라집니다. 영웅 뒤가 막혀 있으면 반대 방향에서 돌진하며, 시간 정지 중에는 예고와 돌진이 함께 멈춥니다.

피격 비네트는 최대 생명력 대비 피해량에 비례한 세기로 화면 가장자리를 붉게 표시합니다. UI 프레임으로 표시해 시간 정지 필터와 겹치지 않습니다. 재발동 대기 중에는 더 큰 피해만 다시 밝히고, 그림자 탈출로 막은 피해에는 표시하지 않습니다.

주기·대열·예고 시간·비네트 세기 등 수치는 `SurvivorConfig.swarmRush`·`SurvivorConfig.hitVignette`에서 관리합니다. 플레이어 대상 설명은 [PATCH_NOTES.md](PATCH_NOTES.md)의 0.1e 항목에 있습니다.

## 무기와 공격 태그

속성과 공격 방식은 별도로 표시합니다. 안야는 화염·번개·냉기·칼날, 퓨트리스는 독·어둠·연금술 속성을 사용합니다. 공격 방식은 아래 여덟 태그이며, **각 영웅 안에서 태그 하나를 정확히 두 무기가 공유**합니다. 한 무기가 여러 태그를 가질 수 있습니다.

| 공격 태그 | 안야 | 퓨트리스 |
| --- | --- | --- |
| 유도 | 잿불 화살·폭풍 구슬 | 죽음의 고리·끓어오르는 플라스크 |
| 관통 | 서리 화살·귀환 칼날 | 역병 침·그림자 낫 |
| 근접 | 순찰자의 칼날·그림자 베기 | 망령의 호위·부식의 숨결 |
| 장판 | 잿불 발자취·납골당의 눈보라 | 역병 발자취·역병 웅덩이 |
| 낙하 | 잿불 낙성·폭풍의 부름 | 역병 단지·산성 약병 산포 |
| 폭발 | 서리 폭발·잿불 낙성 | 휘발성 촉매·역병 단지 |
| 연쇄 | 연쇄 번개·폭풍 구슬 | 영혼 사슬·끓어오르는 플라스크 |
| 소환 | 울부짖는 밴시·그림자 궁수 | 역병 좀비·봉합 실험체 |

태그 정의는 `SurvivorConfig.weapons[id].tags`에서 관리하고 `SurvivorAugments.WeaponTags`·`Description`을 통해 시작 선택·성장 카드·보유 툴팁에 반영합니다. 태그별 전용 강화 효과는 아직 없습니다. 투사체 속도 적용 여부는 별도 `projectile` 플래그로 관리합니다.

### 무기 스탯과 진화

모든 무기의 계산된 성능은 `stats.weapons[id]` 한 곳에 같은 필드 이름(`damage`·`interval`·`count`·`range`·`radius` 등)으로 둡니다. 성장 공식은 엔진별로 정해집니다.

- **코어 엔진**(missile·zone·chain·orbit·strike·cone·pierce): 엔진 기준값은 `SurvivorConfig.weaponEngines[engine].base`, 레벨별 성장표는 같은 항목의 `levels`에 있습니다. 같은 엔진을 쓰는 다른 무기는 `SurvivorConfig.weaponBases`에서 일부 값만 바꿉니다. 엔진의 기준 무기(안야 무기)는 엔진의 기본 연출을 씁니다.
- **프로필 엔진**(nova·field·meteor·summon·orb·boomerang): 무기별 기준값은 `SurvivorConfig.weaponProfiles`에 있습니다. 공통 성장 공식을 쓰며 엔진 항목의 `radiusRange`(범위가 사정거리 보너스로도 증가)·`pulseHaste`(공격 간격이 쿨다운 감소로 단축)로 차이를 둡니다.

엔진 하나는 `SurvivorConfig.weaponEngines`의 항목 하나입니다. 설정 파일에는 데이터(기준값·성장표·`phase`·`carry`·`single`·`volley`·`fixed`·보스 보상 필드)를 두고, 로드 시 `SurvivorAugments`가 성장 공식 `fields`와 툴팁 행 `rows`를, `SurvivorCombatWeapons`가 시전 함수 `cast(id, shot)`를 같은 항목에 등록합니다. 모든 엔진의 시전은 같은 형식입니다. `shot`이 없으면 무기 자신의 현재 능력치로, 있으면 추가 공격 스냅샷(`{weapon, index}`)으로 발동합니다. 진화의 `mode`는 `SurvivorCombatWeapons`의 `modeEngines`에 등록된 엔진에서만 동작하며, 등록되지 않은 조합은 로드 시 오류로 멈춥니다. 엔진을 추가하거나 바꿀 때 이 세 곳을 엔진 이름으로 찾으면 되며, 생명주기·디스패치 코드는 수정하지 않습니다. 함수가 빠진 엔진은 로드 시 오류로 멈춥니다.

- `phase`: 무기 쿨다운 시계는 전투(`SurvivorCombat.TickWeapons`)가 관리합니다. `early` 엔진(프로필 엔진·순찰 칼날)은 상태 갱신 전에, `late` 엔진은 해당 틱의 적 생성 후에 `weaponOrder` 순서로 발동합니다. 시계는 스테이지 시작 시 초기화됩니다.
- `carry`: 장판처럼 초과 시간을 다음 쿨다운으로 넘깁니다. `single`: 추가 공격마다 해당 개수 필드를 1로 줄입니다. `volley`: 기본·추가 칼날을 한 번에 생성합니다.
- `fixed`: 진화가 이 필드를 고정하면 잃는 레벨 성장분(`levels[fixed]`)을 피해 배율로 보존합니다(뇌격·천벌 등).

진화는 `SurvivorAugments`의 진화 목록에서 정의하며 ID는 `<무기>_<키>`(예: `firebolt_burst`)입니다. `multiply`·`add`·`set`은 해당 무기의 스탯 필드를 바꾸고, `status`는 퓨트리스 상태 효과를, `mode`는 전투 동작(`burst`·`focus`·`pulse`·`guard`·`shatter`·`lance`)을 지정합니다. 전투 코드는 진화 ID가 아니라 `mode`를 읽으므로 진화 순서를 바꿔도 동작이 바뀌지 않습니다. `burst`·`focus`·`shatter`·`lance`의 수치(폭발 반경·대상 수·피해율, 중첩 수·지속, 파편 범위·개수·피해율, 빙결 타격 수·시간 등)는 진화 항목의 `modeValues`에 있으며 `stats.weapons[id].modeValues`로 전투에 전달됩니다. 진화 동작의 피해는 시전한 무기의 피해 통계에 포함됩니다.

공격 태그의 글자색은 `SurvivorConfig.weaponTagColors`에서 관리합니다. 유도는 주황, 관통은 하늘색, 근접은 분홍, 장판은 연두, 낙하는 연보라, 폭발은 산호색, 연쇄는 노랑, 소환은 민트색을 사용합니다.

### 주요 공격 동작

- **근접 부채꼴:** 그림자 베기·부식의 숨결은 공격 거리 안의 가장 가까운 살아 있는 지상 적을 조준합니다. 대상이 없으면 바라보는 방향을 사용합니다. 공격이 발동하면 판정·연출 방향을 고정하며 영웅의 방향이나 이동 명령을 바꾸지 않습니다.
- **유도·연쇄 구슬:** 폭풍 구슬·끓어오르는 플라스크는 움직이는 적을 추적하고 대상을 잃으면 다시 찾습니다. 주변 260 내 다른 적 하나에게 피해 35%를 전이하며, 전이 간격은 0.8초이고 전이 피해가 다시 전이되지는 않습니다.
- **낙하:** 역병 단지·산성 약병 산포는 정해진 위치로 낙하합니다. 목표가 이동해도 착탄 위치는 바뀌지 않습니다. 역병 단지는 착탄 시 중독·반응을 적용하며 잔여 장판이 없습니다.
- **잿불 낙성:** 충돌 피해 한 번만 적용하며 장판 피해는 없습니다. ‘재앙의 운석’은 충돌 피해 +80%·쿨다운 20% 증가, ‘잿불 분화구’는 반경 +40%·충돌 피해 +40%입니다.

### 소환 무기

| 무기 | 역할 |
| --- | --- |
| 울부짖는 밴시 | 범위 비명·둔화 |
| 그림자 궁수 | 원거리 화살 |
| 역병 좀비 | 지상 근접·중독 |
| 봉합 실험체 | 지상 범위 내려찍기 |

개체 수 상한·수명·공격 주기는 `SurvivorConfig.weaponProfiles`에서 관리합니다.

소환수는 유닛 모델을 사용하는 ALICE 공격 보조 배우입니다. 충돌·피격·탱킹 없이 가까운 적을 추적하고, 뒤처지면 영웅에게 합류합니다. 개별 수명이 있으며 반복 시전은 수명 갱신과 빈자리 보충으로 처리합니다. 추가 공격 효과는 기존 소환수의 추가 타격으로 적용합니다.

공통 피해·크기·거리·지속 시간·공격 속도 성장을 반영하며 피해는 소환 무기에 귀속됩니다. 메뉴 중에는 이동·공격·수명이 멈추고, 적 시간 정지 중에는 계속 활동합니다. 스테이지 전환·종료·재시작 시 정리합니다.

## 보급 상자와 드롭

### 파괴형 보급 상자

‘낡은 보급 상자’는 외형을 하나로 통일한 나무 상자입니다. 정해진 횟수만큼 공격하면 파괴되고 **파괴 시점에** 회복의 룬·경험치의 서·소멸의 룬·정지의 룬 중 하나를 추첨합니다. 생성 간격·거리·개수·수명, 드롭 확률과 효과 수치는 `SurvivorConfig.bonusProps`에서 관리합니다.

- 영웅 주변의 접근 가능한 위치에 생성하며, 동시 개수 제한이 있고 보스 등장 후에는 추가 생성하지 않습니다.
- 보상은 바닥에 떨어집니다. 가까이 접근하거나 직접 습득하면 소비되어 발동합니다. 가방이 가득 차도 접근 획득이 가능하며, 메뉴 중 습득 효과는 전투 재개까지 대기합니다.
- 상자와 바닥 보상의 수명은 전투 시간 기준입니다. 메뉴 중에는 수명이 멈추고 스테이지 전환·재시작 시 정리합니다.
- 소멸의 룬은 보스를 즉시 처치하지 않고 최대 생명력의 일부만 깎으며 최소 1을 남깁니다. 소멸로 처치해도 경험치·장비 드롭은 적용하지만, 처치 시 무기·세트 연쇄 효과는 발동하지 않습니다.
- 정지의 룬은 보스를 포함한 적과 적 투사체·공격 예고·장판을 멈춥니다. 정지 중인 적은 기존 RGB보다 어둡게 표시하고 종료 시 복원합니다. 영웅·아군 공격·스테이지 시간·적 생성은 계속되며 새 적은 남은 정지 시간을 적용받습니다. 재획득하면 남은 시간을 처음 지속 시간으로 갱신하고, 메뉴 중에는 정지 효과 시간도 멈춥니다.
- 정지 중 전투 화면에는 옅은 청회색 필터를 페이드 인·아웃으로 적용하며 HUD·카드·툴팁은 원래 색을 유지합니다. 메뉴 중에는 숨기고, 전투 재개 시 복원하며, 스테이지 전환·재시작 시 정리합니다.

### 드롭 장비와 적 설정

- 드롭된 장비 모델은 등급별 색상(일반 흰색·희귀 파란색·영웅 보라색)으로 구분합니다. 장신구 장비의 부위는 `장착 부위: 장신구`로 표기합니다.
- 적은 영웅으로부터 최소 거리(`SurvivorConfig.spawnDistance`) 밖에서 생성하며, 구역별 적 수 상한은 `SurvivorConfig.stageEnemyCaps`에서 관리합니다.
- 적 생성은 네이티브 생성 후의 실제 위치도 검사합니다. 경로 보정으로 너무 가까워지거나 지형 조건이 맞지 않으면 재시도하며, 16회 실패하면 해당 생성을 건너뜁니다.
- 근접·원거리 적의 충돌 크기·사거리는 빌드·원본 동기화 도구가 오브젝트 데이터에 반영하며, 같은 타입을 쓰는 정예에도 적용합니다.

### 공용 공격 태그 세트

각 세트는 9개 부위 구성(서로 다른 반지 2개 포함)이며, 두 영웅 모두 획득·장착할 수 있습니다. 해당 영웅의 같은 태그 무기에만 효과를 적용합니다. 세트 카드에는 색상 태그와 현재 영웅의 연계 무기를 표시합니다. 세트 8종의 이름과 2·4세트 효과는 `src/20_system/SurvivorEquipment.lua`의 세트 정의와 [PATCH_NOTES.md](PATCH_NOTES.md)의 0.1d 항목에서 확인합니다.

소환·낙하·관통·유도·장판·연쇄의 4세트 효과는 추가 공격을 제외합니다. 세트가 생성한 폭발·낙하·연쇄 추가 타격은 다른 세트·중독·저주·반응·처치 시 세트 효과를 재발동하지 않으며 원래 무기의 피해 통계에 포함합니다. 정지 중에는 공격·낙하·추적 시간·재사용 시간이 멈추고, 스테이지 전환·재시작 시 누적 횟수·피해 감소·배우를 정리합니다.

유도 강화는 잿불 화살·죽음의 고리와 유도 구슬 모두에 적용하며 구슬의 전이 피해에도 한 번만 반영합니다. 장판 누적은 적·장판별로 따로 계산하고, 추가 공격·상태 잔여물은 제외합니다. 연쇄 종료 추가 타격은 연쇄 번개·영혼 사슬의 마지막 생존 대상, 구슬의 전이 대상에 적용하며, 주변에 다른 적이 없으면 구슬의 단일 대상에도 적용합니다. 근접 피해 감소는 실제 피해 이벤트에서 보호막 흡수 전에 반영하고 세트를 해제하면 즉시 비활성화합니다.

장비의 등급 확률은 유지합니다. 같은 등급 후보에서 보유 무기에 맞는 장비는 가중치 3배, 수집 중인 세트의 아직 장착하지 않은 조각은 추가 2배를 적용합니다. 보스 첫 보상은 기존 유효 강화·세트 완성 우선순위를 유지하며, 위험 보상 첫 후보도 보유 무기 연계를 보장합니다.

## UI와 표기 원칙

- 무기는 영웅 스킬 칸, 성장용 장신구는 기본 인벤토리, 장착 장비는 확장 인벤토리로 관리합니다.
- 성장 카드의 기존 무기 강화는 이번 레벨에서 바뀌는 수치만 전후 비교로 표시하며, 피해에는 증감률을 함께 표시합니다. 신규 무기는 공격 방식·주요 기본 성능을, 진화는 변경 수치·새 기믹·불이익을 표시합니다. 전체 성능은 보유 무기 툴팁에서 확인합니다.
- 무기·진화의 효과 설명 문장에서는 ‘주변 140’ 같은 절대 거리 대신 ‘주변 범위’처럼 표현합니다. 피해율·대상 수·범위 증가율과 능력치 표의 수치 비교는 유지합니다.
- 상단 중복 무기·장신구·장비 관리 프레임과 그림자 탈출 상태 프레임은 표시하지 않습니다. 생존 스킬 버튼·자동 발동·알림은 유지합니다. 상단 HUD는 보스 HP·활성 수색 보호막이 있을 때 표시합니다.
- 미탐사 영역·시야 안개를 해제하고 미니맵·기본 상단 메뉴/자원/시계 장식을 숨깁니다. 하단 초상화·명령창·인벤토리·툴팁과 F10 메뉴 동작은 유지합니다.
- 증강 카드 마우스 오버 발광과 스테이지 보상의 마우스 오버 비교는 사용하지 않습니다. 장신구 설명에 임의 무기 하나를 강화 예시로 넣지 않습니다.
- ‘발동 속도’ 대신 **무기 쿨다운 감소**, 투사체 이동에는 **투사체 속도**를 씁니다. 쿨다운 감소율은 `1 - 1 / (1 + 속도 보너스)`입니다. 속도 보너스 20%는 약 16.7% 감소로 표시합니다.
- 피해판 DPS는 무기 획득 이후 전투 시간 기준입니다. 둔화(초)는 대상별 가장 강한 둔화의 적용 시간을 합산하며, 일시정지 시간은 제외합니다.

## 빌드 상세

### 일반 빌드와 원본 동기화

일반 빌드는 기존 테스트 맵을 입력으로 실행 Lua·에디터 WCT와 도구가 관리하는 게임 오브젝트·툴팁을 갱신합니다. 도구가 관리하는 맵 패치는 `build/lib/map-patches.mjs`의 `mapPatchSteps` 한 목록에 적용 순서대로 있습니다. 테스트 맵 빌드는 각 단계를 맵과 `assets` 스냅샷에 함께 적용해 결과가 같은지 확인하고, 원본 동기화는 `base: true`인 단계(보상 아이템·보급 상자/적 사거리·충돌·성장 오브젝트·아이템 설명·UI 리소스·무기 설명·맵 버전)를 같은 순서로 적용합니다. 새 패치는 이 목록에 추가하고 원본에도 필요하면 `base`와 `apply`를 지정합니다.

통합 Lua의 모듈 `do` 블록은 모두 메인 청크 안에 있어, 한 블록의 활성 지역 변수가 Lua 한도 200을 넘으면 맵 전체가 컴파일되지 않습니다. 빌드는 한도를 넘으면 중단하고, 프로젝트 모듈이 150을 넘으면 경고합니다(외부 라이브러리는 한도만 검사). 경고가 나오면 해당 모듈을 나눕니다.

작성된 지형·배치와 관계없는 MPQ 항목은 보존합니다. **일반 빌드와 원본 동기화는 항상 압축 정리**하며, `--compact`는 이전 명령과의 호환을 위해 허용합니다. 빈 World Editor 맵에서 프로젝트를 처음 생성하는 도구는 아닙니다.

에셋·통합 Lua·맵을 임시 파일로 준비하고 다시 읽어 검증한 뒤, 맵을 마지막에 게시합니다. 변경 전 백업은 `dist/backups/<시간>-build` 또는 `<시간>-before-sync-base`에 저장합니다. 빌드 도중 소스·입력·출력 파일이 바뀌면 덮어쓰기를 중단합니다. 성공 manifest에 실제 출력 경로·프로필을 기록합니다.

### 원본 지형·배치를 수정했을 때

```powershell
npm run build -- --refresh-base --portrait-objects --remove-gold
npm run sync:base
npm test
npm run check -- --refresh-base --portrait-objects --remove-gold
npm run check:base
```

`--refresh-base`는 루트의 실제 원본 맵에서 지형·배치·영역·카메라·에디터 초기화 항목을 가져옵니다. `assets`의 지형 스냅샷을 기준으로 삼지 않습니다. 테스트 맵에 있는 게임 데이터는 보존한 뒤 도구가 관리하는 필드를 갱신합니다.

| 옵션 | 용도 |
| --- | --- |
| `--portrait-objects` | 대화용 `hsPA`·`hsPP` 설치 및 알려진 구모델·방어 타입·업그레이드 필드 이관. 예상하지 못한 충돌은 중단 |
| `--remove-gold` | 알려진 골드 비용·현상금·판매 허용/설명·판매율 정리 |
| `--experience-curve` | `assets/war3mapMisc.txt`의 경험치 곡선 반영 |
| `--base <경로>` | `build`/`check`에서 지형 갱신 기준 원본 지정 |
| `--input <경로>` | 기존 입력 맵 또는 검사할 맵 지정 |
| `--output <경로>` | `dist` 안의 별도 `.w3x` 출력 지정 |

`sync:base`는 루트의 `AnyasLongNight.w3x`를 대상으로 하며 `--check`만 지원합니다. `--base`는 이 명령의 옵션이 아닙니다.

### 파일이 잠겼을 때

게임이나 에디터를 강제 종료하지 않습니다. 테스트 출력이 잠기면 빌더가 시간 접미사 사본을 만들고 실제 경로를 출력합니다. 이때 정식 테스트 맵은 이전 상태로 남습니다. 다음 빌드·검사는 실제 사본을 입력으로 지정할 수 있습니다.

```powershell
npm run build -- --input dist/<실제-출력-파일>.w3x
npm test -- --input dist/<실제-출력-파일>.w3x
npm run check -- --input dist/<실제-출력-파일>.w3x
```

위 `<실제-출력-파일>`은 완료 메시지에 나온 파일명으로 바꿉니다. 원본 동기화가 잠금 때문에 실패하면 World Editor에서 저장을 마치고 파일을 닫은 뒤 `sync:base`를 재시도합니다.

### 제출·개발 프로필

```powershell
npm run build:release
npm run check:release
npm run build:development
npm run check:development
```

| 프로필 | 맵 출력 | 통합 Lua | 진단 |
| --- | --- | --- | --- |
| playtest | `dist/AnyasLongNight-playtest.w3x` | `dist/AnyasLongNight.lua` | 디버그 명령 사용 가능, 성능 계측 기본 꺼짐 |
| release | `dist/submission/AnyasLongNight.w3x` | `dist/AnyasLongNight-release.lua` | 디버그 명령·진단 비활성 |
| development | `dist/AnyasLongNight-development.w3x` | `dist/AnyasLongNight-development.lua` | 상세 진단 사용 가능 |

release/development 빌드의 기본 입력은 정식 테스트 맵입니다. 해당 프로필의 `check`는 기본적으로 그 프로필의 출력 맵을 검사합니다. 제출 파일은 원본·테스트 맵 반영을 마친 뒤 다시 생성합니다. 루트의 동명 파일은 편집용 원본입니다.

## 작업 시 유지할 규칙

1. 게임 변경은 원본·정식 테스트 맵의 Lua/WCT와 필요한 오브젝트·상수·리소스 양쪽에 반영합니다. release는 제출 준비 또는 별도 요청 시 다시 생성합니다.
2. 사용자가 준비한 맵을 오래된 맵이나 생성 데이터로 통째로 덮어쓰지 않습니다. 필요한 항목만 패치하고 관계없는 필드·맵 항목을 보존했는지 다시 읽어 검사합니다.
3. 오브젝트 직렬화는 `row.raw`·`field.raw` 캐시를 재사용합니다. 기존 값을 수정할 때 해당 캐시도 지워야 변경값이 저장됩니다.
4. 에디터의 동시 수정을 고려해 쓰기 직전 기준 파일 변경을 확인합니다. 게임·에디터를 강제 종료하거나 잠긴 파일을 강제로 덮어쓰지 않습니다.
5. World Editor의 오브젝트 저장 충돌 이력이 있습니다. 원인을 단정하지 말고 변경 필드·파일 구조·실제 실행 맵·크래시 로그를 대조합니다.
6. 네이티브 String/Texture에 일반 프레임용 가시성 API를 적용하지 않습니다. 인벤토리 덮개·월드 렌더링 프레임과 선택 유닛별 세부 패널을 수동 가시성 복원 대상으로 추가하지 않습니다. 검정 배경의 실제 import 경로는 `AnyasLongNightUI\Black.tga`입니다.
7. 장면 종료 시 선택 영웅 표시/선택 → 초상화 유닛 제거 → 카메라 복원 → 기본 UI 복원 순서를 유지합니다. 중복·지연 close 콜백이 새 장면을 정리하지 않도록 세대 번호를 확인합니다. Lua `pcall`은 엔진 메모리 오류를 복구하지 못합니다.
8. 정적 검사·네이티브 모의 실행과 실제 Warcraft III/World Editor 검증을 구분합니다.
9. 새 Lua 모듈은 `build/source-order.json`에 의존 순서대로 추가하고, 그 모듈을 읽는 회귀 스위트의 소스 목록(`build/check/harness.mjs`의 `config`·`combat`·`lifecycle`·`uiModules` 등)에도 넣습니다. 회귀 스위트는 모듈 내부 지역 변수를 `Internal(모듈, 이름)`·`SetInternal(모듈, 이름, 값)`으로만 읽고 씁니다. 모듈 이름과 파일의 대응은 `build/check/mocks.mjs`의 `internalFiles` 한곳에 있어, 함수를 다른 파일로 옮기면 그 표만 고칩니다. 같은 이름의 다른 값이 둘 이상이면 오류로 멈춥니다.
10. 한 판에 속한 상태는 모듈 지역 변수로 흩지 않고 실행 상태 테이블에 둡니다. 기본값의 유일한 출처는 전투 `SurvivorCombat`의 `NewRun()`, 생명주기 `AnyasLongNight`의 `NewRun()`·`ResetStageClocks`(레벨 보상 필드는 `SurvivorProgression`이 `Attach`로 받아 씀), 장비 `SurvivorEquipment`의 `NewRun()`, 원정 `SurvivorExpedition`의 `NewRun()`(스테이지 종료 시 기록과 스테이지 번호만 이어받음), 스토리 `SurvivorStory`의 `NewRun()`(단서·대사 기록)·`NewScene()`(열린 장면), 스테이지 `SurvivorStage`의 `NewRun()`(경기장)·`NewPresentation()`(적용된 구역의 장식·지형·통행)입니다. 정리는 네이티브 호출 전에 새 테이블로 바꿔 소유권을 먼저 떼어 냅니다. 판을 넘어 유지하는 값(장비 UI 수정 번호, 장면 세대 번호, 요약 모드·본 장면 기록)만 따로 지역 변수로 둡니다. 분리된 전투 모듈은 같은 테이블을 `Attach`로 받습니다. 회귀 스위트는 개별 지역 변수 대신 `CombatRun()`·`LifecycleRun()`·`EquipmentRun()`·`StoryRun()`·`StoryScene()`·`StageRun()`·`StageView()`·`ExpeditionRun()`으로 이 테이블을 읽고 씁니다.
11. 스테이지별 규칙(수색 지점 배치·보스 약화 단서·위험 보상 등급·용암 주기·광폭화·지원군·근접 크기)은 `SurvivorConfig.encounters[stage]`에 두고 코드에서 스테이지 번호로 분기하지 않습니다.
12. 타격·사망·줍기 루프(Step의 장비 줍기 순회 포함) 안의 상태 오류는 `RunSession.RequestFail`로 미루고, 같은 루프의 알림·대사·효과음·화면 효과·피해 보드 갱신은 `SurvivorUtil.Present`로 감싸 실패를 출력만 합니다. 정지 상태의 플레이어 조작과 인벤토리 감시 타이머·동기화 이벤트의 장비 처리는 `RunSession.IsPending()`도 확인합니다. `GetLocalPlayer` 블록에서는 공유 상태를 바꾸는 함수(장비 관찰, 대사 진행)를 부르지 않습니다.

13. 스테이지 전환(보스 정리 → 막간/엔딩 → 보상 → 결과, 구역 소개 → 준비 → 카운트다운)은 `AnyasLongNight`의 `run.transition` 단계와 전환마다 새로 받는 `run.transitionTicket`으로 관리합니다. 지연 콜백은 자기 단계와 티켓이 현재일 때만 동작하므로, 새 단계를 추가할 때 별도 플래그를 두지 않습니다.
14. 전투 계층(`SurvivorCombat*`)은 UI·원정·네이티브 로드아웃을 직접 부르지 않고 `SurvivorCombat`의 `outside` 포트(분리 모듈은 `Outside`)로만 부릅니다.

AI 에이전트용 추가 지침은 [CLAUDE.md](CLAUDE.md)에 있습니다.

## 실제 플레이와 제출 전 확인

모의 검사 통과는 실제 화면·엔진 동작·성능 확인을 대신하지 않습니다. 특히 **시작 버튼 직후와 첫 대화 마지막 직후**에 크래시 이력이 있으므로 먼저 확인합니다.

- 안야·퓨트리스 선택, 시작 무기·장신구 선택, 소개 → 수동 대사/건너뛰기 → 준비 → 카운트다운 → 이동·첫 적·자동 공격까지의 연결
- 준비 화면·스토리의 검정 배경, 초상화/배우 모델·빨간 팀 색상·카메라·페이드, 빠른 대사 넘김·장면 종료 후 영웅 선택과 기본 UI 복원
- 가방·특성·성장 선택·F10·카운트다운 중 정지, 반복 열기/닫기·취소·수동 재출발, 같은 설정 재도전·설정 변경·오류 후 복구
- 무기 6칸·7레벨·진화·스킬 버튼 배치, 특성 5회 지급/소모, 능력치·재생 표시, 전투 재개 후 의도하지 않은 네이티브 효과가 없는지
- 소환수 모델·수명·상한·합류·정리, 구슬 추적/전이, 낙하 착탄·부채꼴 조준, 보급 상자 파괴·네 보상·보스 8초 정지·색상 복원
- 장비 등급별 바닥 색상, 가방이 찼을 때 선택 보상 보호·추후 수령·반지 비교·습득 중복 방지
- 다섯 구역 지형·장식·관문·수색 동선, 위험 직접 수락/이탈/보상 1회, 전환 시 원본 지형 복원
- 보스 HP·수색 보호막·피해 통계 접기/펼치기, 메뉴·자막 중 HUD 숨김, 한국어 줄바꿈·해상도/UI 배율별 잘림, 미니맵/상단 기본 UI 숨김 유지
- 엔딩 대상·수레 적재·공동 출발의 모델·높이·구도, 난이도별 처음부터 엔딩까지 완주
- 4스테이지 이후 끊김·보스 처치 순간 정리·다음 구역 재개의 성능

### 성능 계측

후반 끊김과 보스 처치 순간 멈춤이 보고되었으며, 최적화 후의 실제 엔진 성능은 별도 측정이 필요합니다. playtest/development에서 보스 처치 **전** 측정을 켜고 다음 구역 전투 재개 후 결과를 확인합니다.

| 채팅 명령 | 동작 |
| --- | --- |
| `-hs perf on` | 집계를 초기화하고 측정 시작 |
| `-hs perf` | 조회·후보·정리·설명 생성 횟수와 Lua CPU 시간 조회 |
| `-hs perf off` | 측정 중단 및 마지막 결과 출력 |

`cleanup.tick`과 `resume.cycle`을 나누어 확인합니다. 네이티브 정리 `cleanup.work`와 ALICE 연결 해제/배우 반환 `cleanup.aliceWork`는 별도 예산입니다. 지형 전환은 `stage.apply`·`stage.clear`·`stage.geometry`·`stage.terrain`·`stage.scenery`와 경로 탐색 계측을 확인합니다.

계측은 기본 꺼짐이며 진행·정리 예산에 영향을 주지 않습니다. `os.clock`이 없으면 횟수만 집계합니다. Lua CPU 시간은 FPS나 엔진 전체 프레임 시간이 아닙니다.

### 맵 정보와 제출 파일

| 항목 | 문구 |
| --- | --- |
| 맵 이름 | 포세이큰: 안야의 긴 밤 `<mapVersion>` |
| 설명 | 스트라솔름에서 스컬지 무리를 벗어난 이름 모를 언데드를 찾아, 안야와 퓨트리스가 로데론 수도 하수구까지 뒤쫓습니다. 포세이큰 왕국 캠페인 직전을 상상한 창작 외전 · 1인용 생존 액션 · 약 25분 |
| 로딩 화면 제목 | 포세이큰: 안야의 긴 밤 |
| 로딩 화면 부제목 | 포세이큰 왕국 이전의 하룻밤 `<mapVersion>` |
| 로딩 화면 문구 | 우클릭으로 이동하고, 무기는 자동으로 공격합니다. 레벨업마다 성장을 선택하고, 수색으로 단서를 모아 다섯 구역을 돌파하세요. |

표의 `<mapVersion>`은 `build/lib/project.mjs`의 `mapVersion` 값으로 채워집니다. 버전을 올릴 때는 이 값만 바꾸고 `build`·`sync:base`를 실행하면 원본·테스트 맵의 `war3map.wts`가 함께 갱신되며, 배포 맵은 다음 `build:release`에서 반영됩니다. 맵 이름·부제목 문구 자체를 World Editor에서 바꾸면 도구가 해당 문자열을 찾지 못해 중단하므로 `installMapVersion`의 패턴도 함께 고칩니다.

미리보기·로딩 이미지는 아직 준비가 필요합니다. 이 맵의 안야·퓨트리스·지하 관문 등으로 제작하며, 상위 폴더의 다른 맵용 ‘로딩스크린, 프리뷰’ 공식 아트는 사용하지 않습니다. 콘테스트의 고해상도 그래픽 기준을 고려해 화면을 확인하고, 최종 `build:release`·`check:release` 후 `dist/submission`의 파일을 제출합니다.
