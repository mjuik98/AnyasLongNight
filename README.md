# 포세이큰: 안야의 긴 밤 — HeroSurvivor

Warcraft III 포세이큰 왕국 커스텀 맵 콘테스트를 목표로 개발하는 Lua 기반 싱글 플레이 생존 게임입니다. 안야와 퓨트리스가 함께 수색하고 이름을 알지 못하는 언데드를 지하로 이송하는 밤을 상상한 **창작 외전**입니다. 가렉이 깨어나는 본편으로 연결하려는 구성이며, 수색 여정·대사·이송 경위는 공식 캠페인에서 확인된 사건으로 취급하지 않습니다.

이 문서는 새 대화에서 개발을 이어가기 위한 인계용 README입니다. 2026-10-03까지의 대화와 작업 기록을 정리했습니다. 아래는 날짜별 구현·검증 이력이며 최신 전체 최적화 결과는 2026-10-03 항목에 있습니다. 후속 작업에서는 현재 소스와 맵을 먼저 대조하세요.

## 2. 게임 구성

- 영웅은 안야(`Uany`), 플레이어 종족은 언데드 고정입니다.
- 이동은 직접 조작하고 무기는 자동으로 공격합니다.
- 총 5스테이지, 스테이지당 5분 구성으로 보스는 4분에 등장하는 흐름입니다.
- 시작 화면에서 난이도·시작 무기·시작 장신구를 선택합니다.
- Warcraft III 영웅 레벨 시스템을 사용합니다. 레벨업 선택지는 카드 3개이며 리롤·제외 기능이 있습니다.
- 무기와 성장용 장신구는 각각 최대 6개입니다.
- 성장용 장신구는 레벨업으로 얻습니다. 몬스터가 드롭하는 장착 장비와 별도 시스템이며, 성장용 장신구는 드롭하지 않습니다.
- 장착 장비는 확장 인벤토리의 총 9개 슬롯을 사용합니다. 레어도·세트 효과·특화 장비가 있습니다.
- 스토리는 한 발화마다 ‘다음 대사’를 눌러 진행하고 마지막에 ‘계속’을 누릅니다. 별도의 ‘장면 건너뛰기’가 있으며, 시간 경과로 대사나 전투가 자동 진행되면 안 됩니다.
- 증강 선택·확장 인벤토리·스토리 중에는 전투와 관련 시간이 정지해야 합니다.
- 콘테스트에서 안내한 고해상도 그래픽 기준을 고려합니다.

## 3. UI와 표기 방향

- 무기는 영웅 스킬 칸, 성장용 장신구는 기본 인벤토리에 표시합니다.
- 상단 무기·장신구 프레임과 별도 장비 관리 프레임은 제거한 방향을 유지합니다.
- 상단 그림자 탈출 상태 프레임·텍스트를 표시하지 않습니다. 스킬 버튼·자동 발동·발동 알림은 유지하며, 상단 HUD는 보스 HP 또는 활성 수색 보호막이 있을 때만 표시합니다.
- 골드 경제를 사용하지 않습니다. 장비 판매가·판매 설명·오브젝트 골드 비용/현상금과 아이템 판매 허용을 제거한 상태를 유지합니다.
- 증강 카드의 마우스 hover glow와 스테이지 보상 hover 비교 기능은 제거했습니다.
- 장신구 설명에는 공통 효과를 표시합니다. 임의의 무기 하나만 강화 예시로 보여주지 않습니다.
- ‘발동 속도’ 대신 **무기 쿨다운 감소**, 투사체 이동 효과는 **투사체 속도**로 구분합니다.
- 쿨다운 감소율은 실제 계산식을 반영합니다. 내부 속도 보너스 수치를 그대로 감소율로 표시하지 않습니다. 예를 들어 속도 보너스 20%가 `기본 주기 / 1.2`로 적용된다면 쿨다운 감소율은 약 16.7%입니다.
- 미탐사 영역과 시야 안개 없이 맵 전체를 보이게 하는 방향입니다.
- 과거 텍스트 겹침·화면 밖 배치·테두리 늘어짐·흰 화면 문제가 있었으므로 기존 해결을 보존합니다.

## 4. 최근 반영한 사항

### 스토리 카메라

스토리 중 유닛을 지하에서 올려다보는 듯한 문제를 수정했습니다. 위에서 내려다보는 구도로 조정하고, 종료 시 거리·각도·회전·높이·롤 등 기존 카메라 설정을 복원하도록 했습니다. 관련 코드는 `SurvivorStory.lua`에서 확인하세요.

### 가방 정리와 장비

- 특정 계열을 보존하고 나머지 장비를 정리하는 기능을 추가했습니다.
- 장착·잠금 장비를 보호하며, 미리보기 후 확인합니다. 확인 시 보호 상태를 다시 검사합니다.
- 아이템을 버릴 수 있는 범위를 크게 늘렸습니다.
- 과거의 일반 8 / 희귀 25 / 영웅 60 판매가 기능은 2026-10-03에 제거했습니다.
- 가방 정리는 삭제입니다. 장착·잠금 보호와 미리보기/확인 절차를 유지합니다.

### 생존 밸런스와 난이도

- 민첩에 의한 방어력·힘에 의한 재생 보너스와 표시용 능력의 의도치 않은 능력치 증가를 제거했습니다.
- 방어력·재생의 성장 폭을 낮췄습니다.
- 난이도 격차는 적 수뿐 아니라 생명력·공격력·공격속도·이동속도로 확대했습니다.
- 적 수에는 상한이 있습니다. 후반 난이도 조정 시 성능 부하를 함께 고려합니다.

### 스테이지 지형과 장식

| 구역 | 시각적 방향 |
| --- | --- |
| 1. 묘역 | 흙길·역병·묘비·뼈·기둥 |
| 2. 용암 구역 | 용암·균열·검은 바위 |
| 3. 얼음 구역 | 눈·얼음·얼어붙은 길·빙하 장식 |
| 4. 폐허 구역 | 포장도로·잔해 |
| 5. 마지막 구역 | 중앙 광장·원형 포장·부서진 기념물 |

동일 장식을 일정 간격으로 나열하는 대신 비대칭 군집과 회전·크기 변화를 적용했습니다. 장식 효과 수를 제한하고 스테이지 전환 시 정리합니다. 관련 코드는 `SurvivorStage.lua`에서 확인하세요.

얼음 스테이지가 흙으로 보이던 원인 중 하나는 맵 지형 팔레트에 눈·얼음 타일이 없던 것이었습니다. `war3map.w3e`에 필요한 타일을 추가하면서 기존 타일 인덱스와 높이·물·절벽 데이터를 보존했습니다. 이후 맵 패치에서도 이 팔레트를 유지해야 합니다.

### 생존 스킬 아이콘 변경 이력

자동 생존 스킬 **‘그림자 탈출’(`HsAE`)**의 아이콘을 다음 경로로 변경했습니다.

```text
ReplaceableTextures\PassiveButtons\PASBTNShadeTrueSight.blp
```

- 수정 필드: `war3mapSkin.w3a`의 `HsAE` → `aart`
- 반영 대상: 편집용 기준 맵, 정식 테스트 맵, `assets/war3mapSkin.w3a`
- 반영 후 맵 내부 경로와 다른 데이터 보존 여부를 확인했습니다.
- 스킬의 성능이나 생존 발동 시 월드 이펙트는 변경하지 않았습니다.
- 게임 내 아이콘 표시 확인과 컴파일은 수행하지 않았습니다.

### 2026-09-24 후반 성능 개선

- 회전검·얼음 투사체·귀환검·지속 베기의 전체 적 순회를 주변 유닛 조회로 변경했습니다. 이동 선분을 포함하는 원으로 후보를 조회한 다음 기존 명중 판정을 적용합니다. 얼음 투사체의 3차원 판정·가까운 순서의 관통, 비행 대상 구분, 동일 대상 재타격 간격을 유지합니다.
- 조회용 그룹은 전투 시작 때 만들고 종료 때 해제합니다. 피해 처리 전 후보 목록을 복사하므로 중첩 피해·사망 처리의 재조회가 바깥 목록을 덮어쓰지 않습니다.
- 보스 처치 후에는 전투와 게임 시간을 멈춘 채 네이티브 타이머로 효과·적을 나눠 제거합니다. 기본 간격은 0.02초, 작업 예산은 24이며 표식·장식도 비용에 포함합니다. 하나의 큰 효과 묶음은 분해하지 않아 단독으로 예산을 넘을 수 있습니다.
- 정리 완료 다음 타이머 호출에서 스토리를 시작합니다. 재시작·종료 시 정리 타이머와 이전 완료 콜백을 취소합니다. 일반 종료·오류 복구의 정리는 동기식으로 유지합니다.
- 무기·장신구 설명문은 성장/장비 능력치 재계산 시 갱신하고, 변경 없는 반복 갱신에서는 캐시를 사용합니다. 일시정지 중 배운 장신구의 표시 지연과 표시 아이템 재생성을 지원합니다.
- 경고 중 아군 효과 투명도는 경고 상태가 바뀔 때 갱신합니다. 새 효과는 생성 시 현재 경고 상태를 적용합니다.
- 보스 등장 안내를 실제 남은 시간 기준으로 변경했습니다. 기본 설정에서는 `남은 60초 안에 처치하세요`입니다.

검증: 소스 19개·맵 스크립트 Lua 5.3 문법 검사, 공간 조회 경계/3차원 후보 누락 검사, 실제 무기 콜백의 재타격·관통·일시정지 검사, 분할 정리·재시작 취소·오류 처리, 설명문 갱신, 5개 스테이지 스토리 대기, 일시정지 사유 중첩 검사를 통과했습니다. Warcraft III 엔진·ALICE 스케줄링·렌더링의 실기 검증은 아닙니다.

고정 모의 배치에서는 180회 조회의 후보 검사가 27,000회에서 1,942회로 감소했습니다. 적 150마리와 칼날 80개 정리는 완료 콜백을 포함해 11회 타이머 호출로 분산되었습니다. 이 수치는 실제 FPS 또는 실제 정리 소요 시간으로 해석하지 않습니다.

### 2026-09-24 선택 보상과 장비 안내 개선

- 보스·봉인 조사에서 직접 선택한 보상은 최초 수령 전까지 바닥 시간 만료와 일반 드롭 개수 제한의 삭제 대상에서 제외합니다. 스테이지를 넘어가도 영웅 발밑으로 옮겨 보존하며, 도전 종료·재시작 때는 정리합니다.
- 미수령 보상은 가방에 빈칸이 생기면 일반 드롭보다 먼저 수령합니다. 직접 선택한 보상이므로 자동 줍기 OFF·등급·중복 필터를 무시합니다. 전투 중에는 기존 줍기 반경 안에서, 휴식 중에는 거리에 관계없이 수령합니다. 수령 후 직접 버린 장비에는 기존의 시간 만료·자동 재수령 방지 규칙을 적용합니다.
- 기존 줍기 버튼 위에 미수령 보상 개수와 자동 소멸 방지 안내를 표시하고, 해당 바닥 아이템 설명에도 보호 상태를 표시합니다.
- 보스 보상의 첫 카드는 기존 등급 확률과 보유 무기 계열을 유지하면서 유용한 미보유 장비를 우선합니다. 현재 장착 상태에서 세트 활성화·미완성 세트 보충·실제 능력치 향상을 비교하며, 가방과 미수령 보상에 있는 장비도 중복 판단에 포함합니다. 쿨다운 하한과 무기 진화의 변환을 반영한 실제 계산값을 사용하고, 활성 세트를 깨는 교체는 우선 추천에서 제외합니다. 적합한 후보가 없으면 기존 관련 후보에서 선택하며, 항상 상위 장비를 보장하는 기능은 아닙니다.

## 5. 남은 확인 사항

### 후반 끊김과 보스 처치 순간 멈춤

사용자가 4스테이지부터 끊김이 증가하고 보스 처치 순간 잠깐 멈추는 현상을 보고했습니다. 위 성능 개선은 이때 확인한 반복 순회와 일괄 제거를 줄인 것입니다. **실제 게임 성능 측정이나 끊김의 근본 해결이 완료된 상태로 간주하지 마세요.** 다음 플레이에서는 후반 전투, 보스 처치, 다음 스테이지 재개를 각각 확인하세요. ALICE 지연 해제의 예산·재사용 안전성은 실제 라이브러리 코드로 모의 검사했지만 실제 엔진 스케줄링·렌더링 비용은 측정하지 않았습니다.

디버그 채팅 명령:

| 명령 | 동작 |
| --- | --- |
| `-hs perf on` | 기존 집계를 지우고 측정 시작 |
| `-hs perf` | 조회 수·후보 수·정리 작업 수·설명문 생성 수와 Lua CPU 시간 출력 |
| `-hs perf off` | 집계를 중단하고 마지막 결과 출력 |

이 명령은 playtest/development 프로필에서 사용할 수 있고 측정은 기본적으로 꺼져 있습니다. `os.clock`이 없는 실행 환경에서는 횟수만 집계합니다. CPU 시간은 Lua 호출에 대한 값으로 프레임 시간이나 FPS가 아닙니다. 측정값으로 게임 진행·정리 예산을 변경하지 않습니다. 보스 처치 전에 켜 두어야 해당 정리가 기록됩니다.

최신 계측에서는 보스 처치 전 `-hs perf on`을 켜고 다음 스테이지 전투를 재개한 뒤 `-hs perf`를 확인하세요. `cleanup.tick`과 `resume.cycle`을 구분할 수 있습니다. `cleanup.aliceWork`는 정지 중 처리한 pair 연결 해제+actor 반납, `cleanup.alicePairs`/`cleanup.aliceActors`는 각각의 개수입니다. 네이티브 `cleanup.work`와 ALICE 작업 예산은 별도로 적용됩니다. 범위 무기는 `.area.orderScans`와 `.area.distanceChecks`를 함께 읽으며, 순서를 유지하는 Lua 순회가 남아 있음을 고려합니다. 실제 전체 엔진 비용이나 FPS를 측정하는 명령은 아닙니다.

스테이지 전환은 `stage.apply` 전체와 `stage.clear`·`stage.geometry`·`stage.terrain`·`stage.scenery` 구간을 따로 기록합니다. `stage.reachability.pathingReads`·`stage.reachability.nodes`와 geometry/terrain cell·scenery effect 수도 함께 확인할 수 있습니다. 켜기 전 지난 전환은 기록되지 않습니다.

피해판 DPS는 무기 획득 후 전투 시간당 피해입니다. 둔화(초)는 가장 강한 둔화의 대상별 적용 시간 합계이며 일시정지 시간은 제외합니다. 시작 직후 길게 출력하던 이 설명은 화면 혼잡을 줄이기 위해 이 문서로 옮겼습니다.

9. 임의의 검증용 스크립트·문서 파일이나 Python 도구를 만들지 않습니다. 별도 파일이 필요하면 사용자의 요청 범위를 먼저 확인합니다.
10. 기존 작업 중인 변경을 되돌리거나 임의로 커밋하지 않습니다. 요청한 범위만 수정합니다.

## 7. 빌드와 검사

Node.js 22 이상이 필요합니다. 프로젝트 루트에서 실행합니다.

```powershell
npm ci
npm test
npm run build
npm run check
```

- `npm test`: 실제 Lua 소스를 Fengari의 Lua 5.3 실행 환경에 읽어 명시적인 Warcraft 네이티브 모의 함수로 회귀 검사를 수행합니다. 맵 파일을 쓰지 않습니다.
- `npm run build`: 현재 정식 테스트 맵의 실행 Lua와 에디터 WCT에서 HeroSurvivor 코드 구간을 함께 교체합니다. 기존 `main`/`config`·별도 사용자 코드·에디터 메타데이터와 지형·오브젝트·스킨·UI 리소스 등 다른 맵 항목을 보존하고 다시 읽어 검사합니다. 편집용 `HeroSurvivor.w3x`는 변경하지 않습니다.
- `npm run check`: 소스·패치 결과의 문법과 다른 맵 항목 보존을 검사하고, 현재 테스트 맵 코드가 소스와 다르면 종료 코드 1을 반환합니다.
- `--remove-gold`: 기존 유닛/아이템 오브젝트와 스킨의 골드 비용·현상금·판매 허용, 알려진 판매 설명, `PawnItemRate`를 정리하고 테스트 맵과 에셋을 함께 저장합니다. 관계없는 필드·문자열·게임 상수를 보존하고 반복 적용 시 내용이 바뀌지 않습니다. 일반 빌드도 골드 제거 상태를 검사합니다. 원본 WTS에 과거 판매 문구가 남아 있으므로 지형 갱신 때는 `npm run build -- --refresh-base --remove-gold --compact`, 검사는 같은 옵션의 `npm run check`를 사용합니다.
- `npm run build:release` / `npm run check:release`: 별도 `dist/HeroSurvivor-release.w3x`와 `dist/HeroSurvivor-release.lua`를 생성/검사합니다. `npm run build:development` / `npm run check:development`는 같은 방식으로 `-development` 산출물을 사용합니다. 두 프로필의 빌드는 기본적으로 정식 테스트 맵을 입력으로 읽고 `--compact`를 수행합니다. `--profile playtest|release|development`와 `--release`를 직접 지정할 수도 있습니다. `--check`의 기본 입력은 선택한 출력 맵이며 `--input`을 명시하면 그 파일을 검사합니다.
- 원본 맵의 크기/지형/배치를 바꾼 뒤에는 `npm run build -- --refresh-base --remove-gold`를 실행합니다. 기본 입력은 기존 정식 테스트 맵, 기준 맵은 프로젝트 루트의 `HeroSurvivor.w3x`입니다. `npm run check -- --refresh-base --remove-gold`로 현재 테스트 맵이 최신 소스와 원본 지형에 맞는지 확인합니다. 다른 기준 맵은 `--base <경로>`로 지정합니다. 이 명시적 모드만 원본 지형/에디터 항목을 가져오고 기존 테스트 맵의 게임 에셋을 보존합니다.
- 대화용 유닛 두 종류를 처음 설치하거나 이전 테스트 맵을 갱신할 때는 `npm run build -- --portrait-objects`를 실행합니다. 이 명시적 모드는 기존 유닛 레코드를 보존하면서 테스트 맵/유닛 에셋에 `hsPA`·`hsPP`를 추가하거나, 이미 설치된 `hsPA`의 알려진 어둠 순찰자 모델을 HeroAnya로, 두 화자의 누락/Normal 방어 타입을 Hero로 갱신합니다. 그 외 같은 ID의 데이터가 충돌하면 중단합니다. 일반 빌드/검사도 필수 초상화 유닛이 없거나 안야가 구모델이거나 방어 타입이 이전 값이면 중단하여 갱신 옵션을 안내합니다. `npm run check -- --portrait-objects`로 맵과 에셋의 일치를 확인합니다. 원본 지형/WCT 동기화와 함께 실행할 때는 `--refresh-base --portrait-objects --remove-gold`를 사용합니다.
- 맵 항목의 내용이 같으면 다시 추가하지 않습니다. 누적된 과거 패치 데이터를 제거할 때는 `npm run build -- --refresh-base --remove-gold --compact`를 실행하며, 저장 후 `npm run check -- --refresh-base --remove-gold --compact`로 내용 일치와 압축 정리 상태를 함께 확인합니다. 원본 변경이 없을 때는 `--compact`만 사용할 수도 있습니다. 일반 빌드는 자동으로 압축 정리하지 않습니다.
- 맵 내용과 선택한 압축 정리 상태가 이미 최신이면 다시 패치하지 않습니다. 실제 맵 갱신 전에는 `dist/backups/<시간>-build`에 입력 맵·이전 통합 Lua·해시 기록을 남깁니다. 소스와 입력/출력 맵이 작업 도중 바뀌었으면 덮어쓰기를 중단합니다.
- 에셋·통합 Lua·맵은 준비한 임시 파일의 재읽기 검증 후 게시하고, 맵을 마지막에 교체합니다. 잡힌 오류에서는 가능한 파일을 이전 상태로 복구하고 외부 변경 파일은 그대로 보존해 백업 복구가 필요한 경로를 보고합니다. 실제 출력 경로와 프로필은 성공 manifest에 기록하며 임시 파일 정리가 실패해도 다른 파일의 정리와 원래 오류 보고를 계속합니다.
- 출력이 게임에 잠겨 있으면 시간 접미사가 붙은 별도 `.w3x`로 저장하고 실제 경로를 출력합니다. 이때 기본 테스트 맵은 이전 상태이므로 실제 출력 파일을 플레이해야 합니다.
- 입력은 기존 테스트 맵이 필요합니다. World Editor가 생성한 빈 스크립트에서 테스트 맵을 처음 만드는 도구는 아닙니다. 오브젝트·스킨·게임 상수·UI 에셋 변경은 자동으로 가져오지 않습니다. 일반 빌드는 실행/에디터 Lua만, `--refresh-base`는 위에 명시한 지형/배치/에디터 항목도 갱신합니다. `assets`의 지형 스냅샷을 갱신 기준으로 쓰지 않고 실제 기준 맵을 읽습니다.

```powershell
npm run build -- --input dist/HeroSurvivor-playtest.w3x --output dist/HeroSurvivor-check.w3x
```
