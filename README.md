# 포세이큰: 안야의 긴 밤 — AnyasLongNight

Warcraft III 포세이큰 왕국 커스텀 맵 콘테스트 출품을 목표로 개발 중인 Lua 기반 싱글 플레이 생존 게임입니다. 안야와 퓨트리스가 함께 수색에 나서 이름 모를 언데드를 지하로 이송하는 하룻밤을 그린 **창작 외전**입니다. 가렉이 깨어나는 본편으로 이어지도록 구성했으며, 수색 여정·대사·이송 경위는 공식 캠페인에서 확인된 사건으로 다루지 않습니다.

이 문서는 새 대화에서 개발을 이어 가기 위한 인계용 README로, 2026-10-10까지의 대화와 작업 기록을 정리했습니다. 4장은 날짜별 구현·검증 이력이며, 최신 전체 최적화 결과는 2026-10-03 항목에 있습니다. 후속 작업을 시작하기 전에 현재 소스와 맵을 먼저 대조하세요.

## 2. 게임 구성

- 영웅은 안야(`Uany`)이며, 플레이어 종족은 언데드로 고정됩니다. 기본 힘·민첩·지능과 레벨당 증가량은 모두 0, 기본 체력은 300, 기본 방어력과 기본 체력 재생은 0입니다.
- 이동은 직접 조작하고, 무기는 자동으로 공격합니다.
- 총 5스테이지로, 보스 등장 / 제한 시간은 1스테이지 2분 / 3분, 2스테이지 3분 / 4분, 3~5스테이지 4분 / 5분입니다. 보스 처치 즉시 클리어하며, 등장 후 처치 제한은 모두 1분입니다.
- 시작 화면에서 난이도·시작 무기·시작 장신구를 선택합니다.
- Warcraft III의 영웅 레벨 시스템을 사용합니다. 레벨업 시 카드 3장 중 하나를 고르며, 리롤·제외 기능이 있습니다.
- 무기와 성장용 장신구는 각각 최대 6개까지 보유하며, 최대 레벨은 7입니다. 무기 진화는 7레벨에서 선택합니다(`SurvivorConfig.growthMaxLevel`).
- 성장용 장신구는 레벨업으로 얻으며 몬스터가 드롭하지 않습니다. 몬스터가 드롭하는 장착 장비와는 별개의 시스템입니다.
- 장착 장비는 확장 인벤토리의 슬롯 9개를 사용하며, 등급·세트 효과·특화 장비가 있습니다.
- 스토리는 발화마다 ‘다음 대사’를 눌러 진행합니다. 마지막 버튼에는 다음 행동이 표시되며, 출발 대화와 2~5구역 도착 대화는 ‘수색 준비’, 중간 대화는 ‘보상 선택’, 엔딩은 ‘결과 보기’입니다. 별도의 ‘장면 건너뛰기’ 버튼이 있고, 대사는 시간이 지나도 자동으로 넘어가지 않습니다.
- 출발 대화와 다음 구역 소개가 끝나면 목표/준비 화면에서 전용 ‘수색 시작’ 버튼을 직접 눌러야 합니다. 클릭 후 3초 카운트다운이 끝나야 전투와 시간이 재개됩니다. 대사 완료·건너뛰기·가방 닫기만으로는 출발하지 않습니다.
- 증강 선택·확장 인벤토리·스토리·수색 준비·카운트다운 중에는 전투와 관련 시간이 모두 정지해야 합니다.
- 콘테스트에서 안내한 고해상도 그래픽 기준을 고려합니다.

## 3. UI와 표기 방향

- 무기는 영웅 스킬 칸에, 성장용 장신구는 기본 인벤토리에 표시합니다.
- 상단 무기·장신구 프레임과 별도의 장비 관리 프레임은 제거한 상태를 유지합니다.
- 상단에 그림자 탈출 상태 프레임과 텍스트를 표시하지 않습니다. 스킬 버튼·자동 발동·발동 알림은 유지하며, 상단 HUD는 보스 HP나 활성 수색 보호막이 있을 때만 표시합니다.
- 골드 경제는 사용하지 않습니다. 장비 판매가·판매 설명, 오브젝트의 골드 비용/현상금, 아이템 판매 허용을 제거한 상태를 유지합니다.
- 증강 카드의 마우스 오버 발광(hover glow)과 스테이지 보상의 마우스 오버 비교 기능은 제거했습니다.
- 장신구 설명에는 공통 효과를 표시하며, 임의의 무기 하나를 골라 강화 예시로 보여 주지 않습니다.
- ‘발동 속도’ 대신 **무기 쿨다운 감소**라는 표현을 쓰고, 투사체 이동 관련 효과는 **투사체 속도**로 구분합니다.
- 쿨다운 감소율은 실제 계산식을 반영하며, 내부 속도 보너스 수치를 그대로 감소율로 표시하지 않습니다. 예를 들어 속도 보너스 20%가 `기본 주기 / 1.2`로 적용되면 쿨다운 감소율은 약 16.7%입니다.
- 미탐사 영역과 시야 안개 없이 맵 전체를 보여 주는 방향입니다.
- 과거에 텍스트 겹침·화면 밖 배치·테두리 늘어짐·흰 화면 문제가 있었으므로 기존 해결 방식을 유지합니다.

## 4. 최근 반영한 사항

### 2026-10-18 전투 대사 화자를 플레이 영웅으로

- 그림자 탈출(`SurvivorCombat`의 `escapeLines`)과 선택 수색·봉인 조사(`SurvivorExpedition`) 자막의 화자가 `"안야"`로 고정돼 있었습니다. 이제 `SurvivorConfig.HeroOf(unit)`가 영웅 유닛 종류로 플레이 영웅을 찾고, 그 영웅의 이름과 대사를 씁니다.
- 퓨트리스 대사 33줄을 추가했습니다: 탈출 5, 수색 단계 12(`beats`), 공략(`insight`)·발견 답(`reply`)·봉인 조사(`riskLine`) 각 5, 봉인 조사 성공 1. 각 장(`chapters[i].putress`)에 두고, 없는 항목은 안야 대사를 씁니다.
- `records[stage].reply`는 안야 대사를 그대로 저장합니다. 구역 사이 스토리 장면(`SurvivorStory`의 `GetSceneReply`/`GetReply`)이 이 값을 쓰기 때문이며, 스토리 대화는 바꾸지 않았습니다.
- 회귀 검사: 모든 장에 퓨트리스 대사가 빠짐없이 있는지, 퓨트리스로 플레이하면 전령 처치·발견 답·공략·탈출 대사가 퓨트리스 화자로 나오는지, 안야는 기존 대사를 유지하는지 확인합니다(화자를 다시 `"안야"`로 고정하면 두 검사가 실패하는 것도 확인). 실제 게임 화면은 확인하지 않았습니다.

### 2026-10-18 영웅 선택과 네 칸 시작 화면 통합

- 퓨트리스 플레이 브랜치(영웅 선택, 무기 12종·진화 24종, 영웅별 장비)와 네 칸 시작 화면 브랜치를 차례로 머지했습니다. 두 브랜치가 각자 영웅 선택을 만들었으므로 네 칸 화면을 기준으로 합쳤습니다.
- `SurvivorConfig.heroes`는 한 표로 합쳤습니다. 각 영웅은 `startingWeapons`·`unitId`(퓨트리스 플레이 쪽)와 `previewSkin`·`previewAnimation`·`story`(시작 화면 쪽)를 함께 가집니다. 퓨트리스 미리보기는 스토리 초상 대역 `hsPP`의 모델을 쓰고, 애니메이션은 `stand`입니다. 퓨트리스 소개문은 안야 소개문의 형식에 무기 설명을 붙여 새로 썼습니다.
- `SurvivorSetupUI`의 영웅 카드는 화면 안에서만 바꾸지 않고 `HeroSurvivor.SelectSetup("HERO", id)`로 게임 쪽에 전달합니다. 영웅이 바뀌면 시작 무기 선택이 지워지고, 무기 목록은 `SurvivorConfig.heroes[영웅].startingWeapons`를 씁니다. 잠긴 영웅(`locked`)은 회색 ‘준비 중’ 카드로 비활성화됩니다. 장신구 미리보기는 선택한 영웅 기준으로 계산합니다.
- 설정 단계(`setupPhase`)는 네 칸 화면 방식대로 항상 `MENU`를 유지하고, `HERO`도 열기·선택 대상입니다. `초기화`(`ResetSetup`)는 난이도·무기·장신구만 지우고 영웅은 유지합니다.
- 회귀 검사: 영웅 목록이 두 명을 보여 주는지, 영웅 카드가 게임 쪽 선택으로 전달되는지, 퓨트리스를 고르면 미리보기 모델과 무기 목록이 바뀌는지 확인합니다(무기 목록을 전역 `startingWeapons`로 되돌리면 실패하는 것도 확인).
- 편집용 원본은 오브젝트 행·필드와 WTS 문자열 단위로 두 브랜치 변경을 합친 뒤 `npm run sync:base`로 실행 Lua·WCT를 반영했습니다. 에셋과 테스트 맵은 빌드로 다시 만들었고, 두 브랜치 변경의 합집합인지 확인했습니다. 실제 게임 화면(특히 퓨트리스 미리보기의 위치·애니메이션)은 확인하지 않았습니다.

### 2026-10-18 ASde에 공통 무기 능력치 6개 추가

- 통합 시 수정: 체력 재생 표시 변경 이후 장비·특성 창에서는 `nativeRegenerationPaused`가 false라서 공통 무기 항목이 0으로 보였습니다. 표시 여부는 모든 정지 사유에서 true인 `stats.combatPaused`(`SurvivorCombat.SetPaused`)로 판단합니다.

- **0.1a의 이름 변경은 적용되지 않았습니다.** `AS07_LABEL`을 `[CustomSkin]`에 넣었는데, 그 섹션은 아이콘 등 그림 경로용입니다. World Editor로 저장된 LoTKT 맵의 `war3mapSkin.txt`를 보면 GlobalStrings 덮어쓰기(`GOLD`, `BONUS_*` 등)는 `[FrameDef]`에 들어갑니다. 빌드는 `[CustomSkin]`에 남은 능력치 키를 지우고, 그 섹션에 다른 내용이 없으면 섹션도 지웁니다. 에디터는 값을 `TRIGSTR_번호`로 저장하지만 여기서는 UTF-8 글자를 그대로 쓰며, 게임에서 정상 적용되는 것을 확인했습니다.
- 값은 숨긴 아이템 능력치 패시브로 넣습니다. 기본 능력과 단위는 설치 클라이언트의 `AbilityMetaData.slk`·`AbilityData.slk`에서 확인했습니다(`build.mjs`의 `statDisplays`).

선택·가방·상세 정보·스토리·수색 준비·카운트다운 중에는 엔진 재생량을 0으로 설정하고, 재계산에서도 이 정지 상태를 유지합니다. 모든 정지 사유가 해제되면 최신 재생량을 복구하며, 종료 시 다시 0으로 정리합니다. 상세 창을 보고 있는 동안에는 실제 회복이 정지하므로 `ASde` 재생도 0으로 표시됩니다. 전투 중 재생량은 기존 장비·능력치 버튼(`ASpc`) 툴팁에서 확인할 수 있으며, 종료 시 원래 툴팁을 복원합니다. 기본·강화 재생량, 정지 중 강화·장비 교체·구역 전환, 최대 생명력 제한, 재시작, 초기화 실패 정리를 모의 검사합니다.

### 2026-10-15 긴 밤의 특성

`ATua`를 기반으로 한 `HsTL`을 추가했습니다. 캠페인 안야의 기본 특성은 유지하지 않고, 5단계에 각 3개씩 총 15개의 능력치 특성을 제공합니다. 내용은 `assets/HeroSurvivorTalents.json` 한 곳에서 관리하며, 일반 빌드가 런타임 Lua 설정과 능력 오브젝트·스킨을 같은 내용으로 생성합니다. 단계별 목록은 메타데이터의 `aabi`(BuffID, 레벨별, 열 0)에 저장합니다. 선택 표식은 기본 힘·민첩·지능 증가가 모두 0인 숨김 패시브여서 기존 6개 무기와 그림자 탈출의 명령 슬롯을 차지하지 않습니다.

### 후반 끊김과 보스 처치 순간 멈춤

사용자가 4스테이지부터 끊김이 늘고 보스 처치 순간 잠깐 멈추는 현상을 보고했습니다. 앞서 기록한 성능 개선은 이때 확인한 반복 순회와 일괄 제거를 줄인 것입니다. **실제 게임 성능을 측정했거나 끊김을 근본적으로 해결한 상태로 간주하지 마세요.** 다음 플레이에서는 후반 전투, 보스 처치, 다음 스테이지 재개를 각각 확인하세요. ALICE 지연 해제의 예산·재사용 안전성은 실제 라이브러리 코드로 모의 검사했지만, 실제 엔진의 스케줄링·렌더링 비용은 측정하지 않았습니다.

디버그 채팅 명령:

| 명령 | 동작 |
| --- | --- |
| `-hs perf on` | 기존 집계를 지우고 측정 시작 |
| `-hs perf` | 조회 수·후보 수·정리 작업 수·설명문 생성 수와 Lua CPU 시간 출력 |
| `-hs perf off` | 집계를 중단하고 마지막 결과 출력 |

이 명령은 playtest/development 프로필에서 사용할 수 있으며, 측정은 기본적으로 꺼져 있습니다. `os.clock`이 없는 실행 환경에서는 횟수만 집계합니다. CPU 시간은 Lua 호출에 걸린 시간이며 프레임 시간이나 FPS가 아닙니다. 측정값은 게임 진행이나 정리 예산에 영향을 주지 않습니다. 보스 처치 시의 정리를 기록하려면 보스를 처치하기 전에 측정을 켜 두어야 합니다.

최신 계측에서는 보스 처치 전에 `-hs perf on`을 켜고, 다음 스테이지 전투가 재개된 뒤 `-hs perf`로 결과를 확인하세요. `cleanup.tick`과 `resume.cycle`을 구분해 볼 수 있습니다. `cleanup.aliceWork`는 정지 중에 처리한 pair 연결 해제와 actor 반납의 합이고, `cleanup.alicePairs`/`cleanup.aliceActors`는 각각의 개수입니다. 네이티브 `cleanup.work`와 ALICE 작업 예산은 따로 적용됩니다. 범위 무기는 `.area.orderScans`와 `.area.distanceChecks`를 함께 보되, 순서를 유지하기 위한 Lua 순회가 남아 있다는 점을 고려하세요. 이 명령으로 실제 엔진 전체 비용이나 FPS를 측정할 수는 없습니다.

스테이지 전환은 `stage.apply` 전체와 `stage.clear`·`stage.geometry`·`stage.terrain`·`stage.scenery` 구간을 따로 기록합니다. `stage.reachability.pathingReads`·`stage.reachability.nodes`와 geometry/terrain cell 수, scenery effect 수도 함께 확인할 수 있습니다. 측정을 켜기 전에 일어난 전환은 기록되지 않습니다.

피해판의 DPS는 무기 획득 이후 전투 시간당 피해량입니다. 둔화(초)는 가장 강한 둔화가 대상별로 적용된 시간의 합계이며, 일시정지 시간은 제외합니다. 시작 직후 길게 출력하던 이 설명은 화면 혼잡을 줄이려고 이 문서로 옮겼습니다.

## 6. 작업 및 맵 패치 주의사항

**사용자 지정 작업 기준(2026-10-15): 앞으로 수정 사항은 원본 `AnyasLongNight.w3x`와 정식 테스트 맵 `dist/AnyasLongNight-playtest.w3x`에 모두 적용합니다.** Lua 변경은 원본과 테스트 맵의 실행 Lua·에디터 WCT까지 동기화하고, 오브젝트·상수·리소스 변경도 필요한 양쪽 항목에 반영합니다. 일반 `npm run build`는 테스트 맵만 갱신하므로 원본 반영을 별도로 확인해야 합니다. 각 맵의 작성된 지형·배치·관계없는 데이터는 보존하고, 완료 전에 양쪽을 다시 읽어 검증합니다. 제출용 release 맵은 제출 준비 또는 별도 요청 시 최신 소스로 다시 생성합니다.

1. 기준 맵에는 사용자가 직접 준비한 오브젝트·지형 등이 들어 있습니다. 오래된 맵이나 생성 데이터로 통째로 덮어쓰지 말고, 필요한 항목만 수정합니다.
2. 이전 작업에서 별도 이름으로 저장한 테스트 맵보다 `dist/AnyasLongNight-playtest.w3x`를 우선합니다. 소스와 산출물이 최신인지는 실제 파일로 확인합니다.
3. World Editor에서 오브젝트를 수정한 뒤 저장할 때 충돌한 이력이 있습니다. 원인을 단정하지 말고 변경된 필드와 파일 구조를 확인합니다.
4. 오브젝트 직렬화 도구는 `row.raw`와 `field.raw`를 재사용합니다. 기존 필드를 수정할 때는 해당 캐시도 지워야 변경값이 직렬화됩니다.
5. 패치 후에는 맵을 다시 읽어 수정값을 확인하고, 관계없는 오브젝트 필드와 맵 내부 파일이 보존됐는지 검사합니다.
6. 사용자가 에디터에서 동시에 수정할 수 있으므로, 쓰기 직전에 기준 파일이 바뀌지 않았는지 확인합니다.
7. 테스트 맵이 게임에 잠겨 있어도 게임을 강제 종료하지 않습니다. 별도 이름으로 저장하고, 사용자에게 실제 결과 파일을 안내합니다.
8. Warcraft III/World Editor에서의 컴파일과 실제 플레이는 사용자가 수행합니다. 에이전트는 정적 검증·모의 실행과 실제 게임 검증을 구분해 보고합니다.
9. 검증용 스크립트·문서 파일이나 Python 도구를 임의로 만들지 않습니다. 별도 파일이 필요하면 먼저 사용자에게 요청 범위를 확인합니다.
10. 진행 중인 기존 변경을 되돌리거나 임의로 커밋하지 않습니다. 요청받은 범위만 수정합니다.

## 7. 빌드와 검사

Node.js 22 이상이 필요하며, 프로젝트 루트에서 실행합니다.

```powershell
npm ci
npm test
npm run build
npm run check
```

- `npm test`: 실제 Lua 소스를 Fengari의 Lua 5.3 실행 환경에 불러와, 명시적인 Warcraft 네이티브 모의 함수로 회귀 검사를 수행합니다. 맵 파일은 쓰지 않습니다.
- `npm run build`: 현재 정식 테스트 맵의 실행 Lua와 에디터 WCT에서 HeroSurvivor 코드 구간을 함께 교체합니다. 기존 `main`/`config`, 별도 사용자 코드, 에디터 메타데이터와 지형·오브젝트·스킨·UI 리소스 등 다른 맵 항목은 보존하며, 저장 후 다시 읽어 검사합니다. 편집용 `HeroSurvivor.w3x`는 변경하지 않습니다.
- `npm run check`: 소스와 패치 결과의 문법, 다른 맵 항목 보존을 검사하고, 현재 테스트 맵의 코드가 소스와 다르면 종료 코드 1을 반환합니다.
- `--remove-gold`: 기존 유닛/아이템 오브젝트와 스킨의 골드 비용·현상금·판매 허용, 알려진 판매 설명, `PawnItemRate`를 정리하고 테스트 맵과 에셋을 함께 저장합니다. 관계없는 필드·문자열·게임 상수는 보존하며, 반복 적용해도 결과가 달라지지 않습니다. 일반 빌드도 골드 제거 상태를 검사합니다. 원본 WTS에 과거 판매 문구가 남아 있으므로, 지형을 갱신할 때는 `npm run build -- --refresh-base --remove-gold --compact`를, 검사할 때는 같은 옵션의 `npm run check`를 사용합니다.
- `npm run build:release` / `npm run check:release`: 제출용 `dist/submission/AnyasLongNight.w3x`와 `dist/AnyasLongNight-release.lua`를 생성/검사합니다. `npm run build:development` / `npm run check:development`는 `AnyasLongNight-development.w3x`/`.lua` 산출물을 다룹니다. 두 프로필의 빌드는 기본적으로 정식 테스트 맵을 입력으로 읽고 `--compact`를 적용합니다. `--profile playtest|release|development`와 `--release`를 직접 지정할 수도 있습니다. `--check`의 기본 입력은 선택한 출력 맵이며, `--input`을 명시하면 해당 파일을 검사합니다.
- 원본 맵의 크기/지형/배치를 바꾼 뒤에는 `npm run build -- --refresh-base --remove-gold`를 실행합니다. 기본 입력은 기존 정식 테스트 맵이고, 기준 맵은 프로젝트 루트의 `HeroSurvivor.w3x`입니다. `npm run check -- --refresh-base --remove-gold`로 현재 테스트 맵이 최신 소스와 원본 지형에 맞는지 확인합니다. 다른 기준 맵은 `--base <경로>`로 지정합니다. 원본 지형/에디터 항목은 이 명시적 모드에서만 가져오며, 기존 테스트 맵의 게임 에셋은 보존합니다.
- 대화용 유닛 두 종류를 처음 설치하거나 이전 테스트 맵을 갱신할 때는 `npm run build -- --portrait-objects`를 실행합니다. 이 명시적 모드는 기존 유닛 레코드를 보존하면서 테스트 맵/유닛 에셋에 `hsPA`·`hsPP`를 추가합니다. 이미 설치되어 있다면 `hsPA`의 알려진 어둠 순찰자 모델을 HeroAnya로, 두 화자의 누락/Normal 방어 타입을 Hero로 갱신하고 상속/명시된 `Rguv` 업그레이드 목록을 비웁니다. 그 밖에 같은 ID의 데이터가 충돌하면 중단합니다. 일반 빌드/검사도 필수 초상화 유닛이 없거나, 안야가 구모델이거나, 방어 타입/업그레이드가 이전 값이면 중단하고 갱신 옵션을 안내합니다. `npm run check -- --portrait-objects`로 맵과 에셋의 일치를 확인합니다. 원본 지형/WCT 동기화와 함께 실행할 때는 `--refresh-base --portrait-objects --remove-gold`를 사용합니다.
- 맵 항목의 내용이 같으면 다시 추가하지 않습니다. 누적된 과거 패치 데이터를 제거하려면 `npm run build -- --refresh-base --remove-gold --compact`를 실행하고, 저장 후 `npm run check -- --refresh-base --remove-gold --compact`로 내용 일치와 압축 정리 상태를 함께 확인합니다. 원본 변경이 없으면 `--compact`만 사용해도 됩니다. 일반 빌드는 자동으로 압축 정리를 하지 않습니다.
- 맵 내용과 선택한 압축 정리 상태가 이미 최신이면 다시 패치하지 않습니다. 실제로 맵을 갱신하기 전에는 `dist/backups/<시간>-build`에 입력 맵·이전 통합 Lua·해시 기록을 남깁니다. 작업 도중 소스나 입력/출력 맵이 바뀌면 덮어쓰기를 중단합니다.
- 에셋·통합 Lua·맵은 임시 파일로 준비해 다시 읽어 검증한 뒤 게시하며, 맵은 마지막에 교체합니다. 예외가 잡히면 가능한 파일은 이전 상태로 복구하고, 외부에서 변경된 파일은 그대로 두어 백업 복구가 필요한 경로를 보고합니다. 실제 출력 경로와 프로필은 성공 manifest에 기록하며, 임시 파일 정리가 실패해도 나머지 파일 정리와 원래 오류 보고는 계속합니다.
- 출력 파일이 게임에 잠겨 있으면 시간 접미사를 붙인 별도 `.w3x`로 저장하고 실제 경로를 출력합니다. 이 경우 기본 테스트 맵은 이전 상태로 남아 있으므로 실제 출력 파일로 플레이해야 합니다.
- 입력으로 기존 테스트 맵이 필요합니다. World Editor가 생성한 빈 스크립트에서 테스트 맵을 처음 만드는 도구는 아닙니다. 오브젝트·스킨·게임 상수·UI 에셋 변경은 자동으로 가져오지 않습니다. 일반 빌드는 실행/에디터 Lua만 갱신하고, `--refresh-base`는 위에 적은 지형/배치/에디터 항목도 갱신합니다. 갱신 기준으로는 `assets`의 지형 스냅샷이 아니라 실제 기준 맵을 읽습니다.

별도의 테스트 사본을 만들 때는 다음과 같이 지정합니다.

```powershell
npm run build -- --input dist/AnyasLongNight-playtest.w3x --output dist/AnyasLongNight-check.w3x
```
